# Lessons

Numbered L-n. Each lesson names the failure, the rule it produced, and where that rule is enforced.

| ID | Lesson | Rule | Enforced by |
| --- | --- | --- | --- |
| L-1 | A gate that has never failed is a gate nobody has checked (carried over from Kova) | Every gate ships a `--self-test` that feeds it bad input and expects FAIL | `node_converge.py --self-test`, `tests/harness/` |
| L-2 | W0.1 verifier: the proofs gate accepted a test name found only in a comment, a string, a prefix or a skipped test | Proofs resolve through `ast` to a real, unskipped `def test_*` under `tests/`; `logical` can never be n/a | `node_converge.proof_problems` |
| L-3 | W0.1 verifier: a failed `git diff` against a bad `.base` was ignored, so gate 11 passed | A tool error inside a gate is a FAIL, never "no changes" | `node_converge.changed_files` |
| L-4 | W0.1 verifier: gate self-tests passed even when ruff, pyright or pytest were not installed | A self-test must require the planted defect's identity (rule code, file, test name) in the output, not just a non-zero exit | `node_converge.self_test` |
| L-5 | W0.1 verifier: running node-start in check-only mode silently moved the changed-tests baseline | Check-only commands never write; baselines are written once, by `--mark-building`, and only `--reset-base` overwrites them | `node_start.start` |
| L-6 | Local Python is 3.12 but the floor is 3.11; a backslash in an f-string expression slipped in | pyright runs with `pythonVersion = "3.11"`, and CI tests 3.11 | `pyproject.toml`, `ci.yml` |
| L-7 | First CI run: Windows checkout turned LF into CRLF, so the byte-identical catalog round-trip failed on all three Windows jobs | `.gitattributes` forces LF for every text file | `.gitattributes`, `test_catalog_round_trip_is_byte_identical` on windows-latest |
| L-8 | N1.1 verifier: pydantic `frozen=True` is shallow; `record.claims.append(...)` changed the object's JSON | Sequence fields are tuples, mappings are `FrozenDict`, free-form JSON goes through `deep_freeze` | `evalkit/schemas/_base.py`, `test_records_are_deeply_immutable_and_hashable` |
| L-9 | N1.1 verifier: pydantic floats accept infinity, which dumps as `null` and fails to load back | `allow_inf_nan=False` on the base model and every float type | `test_non_finite_floats_are_rejected` |
| L-10 | N1.1 verifier: a test that loops over `__all__` can never find a missing export | Contract tests compare against an independent list taken from the spec | `test_every_tech_spec_schema_is_exported` |
| L-11 | N1.4: two scripted text replacements silently matched nothing after ruff reflowed the file; one fix only landed by luck | Every scripted edit asserts its match count before writing (`assert t.count(old) == 1`) | builder practice; the full-dataset splitter check caught it |
| L-12 | N1.3 verifier: a NaN or negative cost estimate made `spent + in_flight + est > cap` always false, switching the spend cap off | Every money value entering the executor is checked finite and non-negative; a bad value is an error, never a pass | `_check_amount`, `test_bad_estimates_are_errors_not_bypasses` |
| L-13 | N1.3 verifier: hashing only the class body missed base-class and schema changes, and a class rename dodged the bump check | The version manifest is keyed by the cache-key `name` and hashes every Node class in the MRO plus `In` and `Out` | `versions.behaviour_hash`, `test_base_class_change_requires_a_bump` |
| L-14 | N1.3 verifier: budget was reserved before the concurrency slot, so queued calls blocked each other; identical inputs were paid for twice | Reserve inside the slot; coalesce identical in-flight keys | `test_queued_calls_do_not_hold_budget`, `test_duplicate_inputs_in_one_map_are_coalesced` |
| L-15 | A background verifier ran `uv` with a different Python and rebuilt the shared `.venv` while converge was running, failing 6 gates spuriously | Verifiers run with `UV_PROJECT_ENVIRONMENT` set to a private scratch directory | verifier prompt template |
| L-16 | N1.4 verifier: the data card stated two things in the present tense that were not yet true, and the probe spec left seed, checker and replacement rule open | Docs describe what is true now and name the node that will make the rest true; a spec is complete only when two people would implement it identically, and a test pins each value | `test_data_card_claims_match_the_code`, `test_paraphrase_probe_spec_is_complete` |
| L-17 | N1.2 verifier: fakes built flatter than the real SDK hid a wrong error-type path, and an expired batch discarded billed results | Fakes for SDK objects are built from the SDK models where possible; a terminal-but-failed batch still reads its output files | `test_anthropic_errored_item_keeps_the_real_sdk_error_type`, `test_expired_openai_batch_keeps_finished_results` |
| L-18 | CI on Windows: concurrent `os.replace` onto one file raises PermissionError, which macOS never shows | Content-addressed writes are first-writer-wins; a refused replace onto an existing target counts as a lost race; CI on Windows is the proof, not a local run | `store._replace`, `test_concurrent_puts_of_one_key_are_safe` on windows-latest |
| L-19 | A2.2 verifier: a plugin could replace a built-in scorer through the public decorator, and a broken plugin reloaded on every lookup | Registries refuse existing names, snapshot built-ins and restore them after plugins load, and remember failed plugins | `test_plugin_cannot_replace_a_builtin_via_the_decorator`, `test_broken_plugins_load_once_and_bad_metadata_is_survivable` |
| L-20 | CI installed the project without its optional extras, so pyright could not resolve the provider SDKs; local runs always had them | CI tests with `--all-extras`, and a separate core-only job proves `import evalkit` works without either SDK; after every push, read the CI result before starting the next node | `ci.yml`, `test_ci_workflow_covers_gates_and_matrix` |
| L-21 | A2.1 verifier: budget exhaustion and config errors (bad key, missing adapter) were recorded as provider "transport" failures, so a broken run looked finished; the parser accepted prose around a JSON object | Only transient provider errors become `transport`; budget and configuration errors stop the run; answers must be exactly one JSON object; a node whose helper changes gets a manual `code_version` bump | `test_budget_exhaustion_stops_the_run_instead_of_recording_failures`, `test_prose_around_json_is_a_schema_error` |
| L-22 | S2 verifier: bucketing rows by rounded values made the unordered matcher accept values outside tolerance, and a greedy pass missed valid pairings | Tolerant matching is exact-first, then a maximum bipartite matching with a tolerance window; fuzz tests compare against brute force | `test_unordered_never_accepts_values_outside_tolerance`, `test_matcher_agrees_with_brute_force_on_small_sets` |
| L-23 | A2.3 verifier: the version check could not see a prompt kept as a module constant, extraction aborted the whole stage on one failure, and nothing guarded B11 | Attach prompts to the node class (hashed by value); every model-calling stage uses the same per-item error taxonomy; specs written as "must not" need an executable guard or an explicit note of what only humans check | `test_prompt_edits_are_caught_by_the_version_check`, `test_extraction_transport_failures_are_per_item`, `test_claims_that_add_or_drop_content_are_rejected` |
| L-24 | A2.4 verifier: one batch id per run meant expired batches were never resubmitted and a partial cache re-paid for every claim; custom ids leaked claim ids; a pending batch's spend was not held against the cap; polling could sleep past `max_wait_s`; only claims were scrubbed of model names; verdicts could cite evidence that contradicted them. Pass 2: prefix redaction corrupted words like "solution"; a new process did not re-hold committed batch spend; an exception mid-collection leaked the hold; concurrent calls double-submitted; retry spend was unreported; transient retry failures were cached | Track batch membership per item (meta per claim, deleted when the verdict lands or the item fails transiently); budget holds are explicit (`hold_batch` / `settle_batch`, released once); bound every sleep by the deadline; redact every judge-visible string whole-word; verdict, evidence and quote must agree. Store what a resume needs (the estimate) with the pending item; settle in `finally`; serialise scan-and-submit; test redaction against the real fixture, not hand-picked strings; fakes must yield where real I/O does. Pass 3: hold the per-judge lock through collection, collect paid batches even when fresh work does not fit the budget, stop only on configuration errors, and record a claim's cost when it is resolved, not when it is seen. Pass 4: a collect timeout must cover the results download, not just a status check; accept the wrappers the prompt itself invites; never cache a provider error | `test_expired_batch_items_are_resubmitted_on_the_next_run`, `test_partial_cache_only_submits_the_missing_claims`, `test_open_batch_holds_budget_until_collected_and_releases_once`, `test_redaction_is_whole_word_on_claims_and_sentences`, `test_redaction_never_changes_real_abstracts`, `test_resume_in_a_new_process_reholds_committed_batch_spend`, `test_concurrent_calls_for_one_judge_submit_once` |
| L-25 | A2.5 verifier: missing per-judge scores became 0.0, the calibrated stamp ignored task and rubric, dead models passed cost and latency bars, and no test exercised Holm (2-model fixtures have one pair per family) | Never default a missing score; tie every stamp to the exact inputs it certifies; mutation-test statistical code with at least 3 groups so corrections actually bite | `test_stale_records_missing_a_finished_judge_are_refused`, `test_calibrated_only_with_agreement_for_every_judge_on_this_task_and_rubric`, `test_a_model_whose_calls_all_failed_fails_every_threshold`, `test_holm_turns_an_unadjusted_separation_into_a_tie` |
| L-26 | A2.6 verifier: stratum-ordered sheets revealed the model, label keys were not bound to claim text, a relabel on the first-pass file overwrote it, a 3-claim judge could be certified, a rubric change could reuse the held-out set, and symmetric test tables hid formula errors | Bind every human input to the exact content and round it was given for; enforce protocol rules in code, not only in the guide; pin statistics with asymmetric hand-computed cases and an independent recomputation | `test_labels_from_another_run_never_attach`, `test_relabel_round_refuses_the_first_pass_file`, `test_a_judge_must_cover_the_held_out_claims`, `test_a_held_out_set_scored_under_another_rubric_is_refused`, `test_kappa_on_an_asymmetric_table_and_confusion_orientation` |
