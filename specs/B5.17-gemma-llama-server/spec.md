# B5.17 — Gemma through llama-server: worked example and /gemma/ page

**Wave 5 (after v0.4.1). Depends on:** N1.2 (the `openai_compatible` adapter, ADP-08), B2.3 (report page and Pages deploy), B5.12 (citation precision and aim-citation rate in the summary). **Asked by:** Gemma Grounded Health (GGH), its R4.4 upstream contribution, approved by its owner (GGH OWNER D-64). No source change under `src/`.

## Capabilities
- **GEM-01**: a worked example in `docs/plugins.md` of how GGH scored a local GGUF (Gemma 4 E2B fine-tune, `gemma-e2b-grounded-v2-q4`) served by llama-server's OpenAI-compatible endpoint, through EvalKit's `endpoints` route to the `openai_compatible` adapter. Every value is GGH's real one: the run config (GGH `configs/evalkit_v2.yaml`) and the server flags (GGH `src/ggh/serve/llama.py`: `--jinja --reasoning off --reasoning-budget 0 --temp 0 --top-k 1 --seed 7 --parallel 1`, plus host, port, GPU layers, threads, context and `--no-webui`). The gotchas GGH hit: Gemma 4's thinking channel must be off (llama-server `--reasoning off --reasoning-budget 0`, GGH D-41; Ollama `--think=false`, GGH R4.2 known issue); one llama-server slot means requests queue, so `concurrency: {openai_compatible: 1}`; EvalKit sends no sampling parameters, so greedy decoding is the server's job; the answer cache key names the model alias and request, not the endpoint URL or the GGUF, so a new GGUF needs a new model name.
- **GEM-02**: `examples/llama-server/evalkit.yaml`, a run config for a llama-server-served model, loaded by `evalkit.config.load_run_config` in a test with no network; the test also checks the routing (`openai_compatible`), that no effort is sent to the endpoint, one request at a time, and that the YAML block in `docs/plugins.md` is the file.
- **GEM-03**: a `/gemma/` site page. `docs/gemma/` holds GGH's committed `docs/results/main_v2/summary.json`, `run.json` and `charts.vl.json` byte for byte (sha256 and GGH's commit recorded in `docs/gemma/source.json`), and `docs/gemma/index.html` rendered from them by `scripts/build_gemma_page.py` with EvalKit's own renderer (`evalkit.report.html.render_report`). Per-case records are never copied (no `records.jsonl`, no `cases.jsonl`); the renderer's failure explorer is replaced by a note saying so. The page adds one card, from `source.json`, that states: the judge (gpt-6.1-sol alone, gpt-6-luna extracting claims); GGH's per-judge calibration stamp as its results bundle words it (Sol calibrated against a Claude Opus 5.5 reference labeller: a model's labels, not a human expert's), beside EvalKit's per-run "uncalibrated" stamp, which the summary keeps (GGH D-59); the aim-rule caveat (v2-vs-base citation results depend on how the judge applies the citation check's aim rule) with a link to GGH's `docs/measurements/aim_rule_check.json` on GitHub; the Hugging Face model and GGUF repos. `--check` rebuilds the page and compares bytes and runs the content checks (required statements present, no case id, no per-case record, copied files match their recorded sha256); `--ggh <checkout>` also cross-checks `source.json` against a GGH checkout; `--self-test` plants each defect and requires the check to fail.
- **GEM-04**: `.github/workflows/pages.yml` copies `docs/gemma/` to `_site/gemma/` when `docs/gemma/index.html` exists (the same guard as the index), and `docs/gemma/**` is in the push paths.

Also (not a capability): `ISSUE-aim-rule.md` in this folder, a drafted, unfiled GitHub issue on the citation rubric's aim rule (rubric hash `be34ebe577bc96ae`) with GGH's evidence and a proposed clarification.

## Goal
A reader with a GGUF on a laptop can score it with EvalKit by copying one config and one server command, knowing the three things that silently change results; and a public page shows one downstream project's real run, rendered by EvalKit, with every caveat its source carries and nothing its source does not state.

## Rules
1. The page shows only what its sources state: numbers from the copied `summary.json` (through the renderer) and statements from `source.json`, each of which names the GGH file it was read from.
2. No case id (`pqa-<digits>`) and no isolated number of 7 or more digits on the page; no `<details>` failure items; no `records`/`cases` file in `docs/gemma/`.
3. No network in any test; paths through `pathlib` only (CI runs Linux, macOS and Windows).
4. Nothing here changes EvalKit's behaviour or public API.
