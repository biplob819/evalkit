# B5.7 acceptance criteria

**LED-01** Run history: `evalkit history add` appends one hash-chained `ledger-1` line per run (summary hash, config hash, code and EvalKit versions, date, metrics with held-out rows folded to split level) through B5.14's `append_entry`; a run is recorded once, a pending run is refused (exit 4), a cap-stopped run is recorded but excluded from bands (exit 3); `evalkit history verify` checks the chain and append-only against CI revisions; `evalkit history show` lists every metric [D-62]
**LED-02** Trend and alarm bands per (metric, labels) from at least 5 comparable prior runs (last 20, after any `band_reset`): centre median, spread max(1.4826·MAD, median SE of the history, SE of the new run); warn beyond 2·spread, alarm beyond 3·spread (exit 1), on the failing side only for a gated metric; fewer than 5 runs is `learning` and never flags [D-62]
**LED-03** Experiment ledger: hypothesis, change, a primary metric and direction declared at open; before and after stored as compare's output with its CIs and a verdict (supported, refuted, inconclusive); the freeze guard reserves one held-out look per frozen candidate as a B5.14 `heldout_scored` line (`look:<candidate sha256>`, every case of the split) before scoring, and a second look for the same candidate exits 1 with nothing written; held-out results only as split aggregates [D-62]
**LED-04** Drift and calibration monitor: per-feature PSI between a frozen, hashed reference and a new batch, from rows (reference deciles, `[e_i, e_{i+1})`, shares floored at 1e-4; equal to fraud-review-bedrock's `psi`) or from pre-binned shares (respectful-offers); Brier, ECE and reliability-bin deltas with 95% intervals, each against an alarm band (changed after Holm, warn when worse, alarm when the interval lies beyond a tolerance); bins that do not align are reported, not compared [D-63]
**LED-05** PSI levels default ok below 0.1, warn 0.1 to 0.25, alarm above 0.25 (fraud-review-bedrock MON-03), overridable per feature; a deterministic trend chart per metric (values with intervals, median, warn and alarm bands, flags by shape and label, settings changes marked) and a PSI panel in `evalkit report --history` and `evalkit history show --html` [D-65]
**LED-06** Spend ledger: chained `spend-1` JSONL (EvalKit's legacy lines sealed), `evalkit spend check` against a cap per total, UTC day or UTC month: alarm at a set fraction (default 0.8, course-assistant 0.9) printed with exit 0; cap reached, or an estimate that would exceed it, exit 3; other projects' ledgers read through a field map [D-65]
**EFF-03** Efficiency run-to-run variation per project and model: LED-02 bands on cost, tokens, cache-hit share and latency; a spread table (median, MAD spread, coefficient of variation, min, max, latest); a cost flag after a price-table change is marked `price_date changed`, a cache-hit drop `cache regression` [D-67]

Every criterion: no held-out id, id hash or text in any ledger line or output; exit codes 0/1/2/3/4 with precedence 2 > 3 > 4 > 1 > 0; tests across logical, contract, golden, repro and safety (spec.md, Tests).
