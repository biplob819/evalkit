# B5.15 acceptance criteria

**SQE-01** Opt-in `sql_match` equivalences, each off by default and named per call, never turning a wrong answer into a match: percent_scale (a gold column named as a percent by whole words — pct/percent/percentage, or points+change for percentage-point questions; never percentile — matches a predicted fraction ×100, only when the question asks for a percentage and does not negate it; the percent column alone gets a 0.01 tolerance), pivot (a long gold label+value table matches one wide predicted row; an extra zero column must look like an omitted label, never a summary word), empty_check (an expected-empty gold matches one row whose count-named columns are all 0; other cells null or ISO dates), period_number (month/quarter-start DATEs match a gold column named month or quarter, in a year the question names) [D-71]
**SQE-02** Strict `sql_match` values and reasons are unchanged by default (failure details made deterministic across hash seeds and regenerated once); results record `correct_strict` and which equivalence matched; agentic-analytics' 8 baseline cases and its D-81/D-91 reference tests are EvalKit tests, and EvalKit is at least as strict as the reference (a638db9) [D-71]
