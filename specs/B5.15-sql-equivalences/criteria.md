# B5.15 acceptance criteria

**SQE-01** Opt-in `sql_match` equivalences, each off by default and named per call (`equivalences=(...)`, with `question=` text): percent_scale (the question asks for a percentage — not share, proportion or percentile — `abs_tol >= 0.01`, and a gold column named pct/percent/points matches a predicted fraction ×100 that fits only once scaled), pivot (a long gold of distinct text labels + numbers matches one wide predicted row whose column names are the labels, case- and separator-insensitive; any extra predicted column must be numeric zero), empty_check (an empty gold matches one predicted row with at least one numeric cell, every numeric cell 0 and every other cell text or null), period_number (predicted month-/quarter-start dates in one calendar year match gold month 1–12 or quarter 1–4 numbers only when the question names months/quarters); unknown names are rejected [D-71]

**SQE-02** Strict `sql_match` is unchanged by default (existing fixtures and a pre-change output snapshot byte-identical); strict is evaluated first and a strict pass is never relabelled; with equivalences named, details record `correct_strict` and the `equivalences` that matched (plus `strict_reason` on a rescue), so strict and lenient scores sit side by side; agentic-analytics' baseline cases (percent q-006/q-047/q-085, pivot q-005/q-057, empty check q-020/q-040, quarter as date q-025) are tests, lifted with its 42 tests from its local reference implementation (f6abdec) [D-71]
