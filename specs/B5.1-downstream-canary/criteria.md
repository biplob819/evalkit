# B5.1 acceptance criteria

**DSC-01** `docs/downstream.tsv` lists the seven projects with the ten columns; every row parses, repos are `owner/name`, `tests` is `auto`, `all` or `none`, `install` holds only `--extra`/`--group` arguments; `deselect` and `known` hold only pytest node ids (functions or class methods); the opt-in online check confirms each recorded pin against the project's `pyproject.toml` on its branch.
**DSC-02** `scripts/downstream_imports.py` lists every EvalKit import in a checkout by module and name with a file count, classes each as `public` (including a public module imported whole), `public-elsewhere`, `internal` or `private` from the public contract, never imports downstream code, skips only VCS, cache and virtual-environment folders (not folders merely named like one), counts only `test_*.py`/`*_test.py` files as tests, reports unparsable files without stopping, prints the EvalKit-importing test files with `--tests`, emits stable JSON with `--json`, and passes its `--self-test`.
**DSC-03** `downstream.yml` builds its matrix from the registry, runs each `auto` project's EvalKit-importing tests with this checkout installed over the pin, `-m "not live"` and the registry's pin-identity tests deselected, has no secrets or API keys and read-only permissions, does not fail fast, keeps no credentials on disk, and uploads a per-project artifact; the child environment is an allowlist with a throwaway HOME; a run that collects nothing or skips everything is `nothing-ran`, failures only on `known` ids are `known-drift`, stale node ids and a checkout holding `.env` are `setup-error`, and counts come only from pytest's final summary line; `scripts/downstream_canary.py` runs the same steps on local checkouts, and a recorded baseline run against all `auto` projects is stored in `docs/measurements/`.
