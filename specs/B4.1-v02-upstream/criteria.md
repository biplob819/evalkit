# B4.1 acceptance criteria

**SUT-01** A `SystemAdapter` registered by name (decorator or the `evalkit.systems` entry-point group) and routed from `evalkit.yaml` `systems:` is called once per case with the full `Case` (id, question, context, meta) and the rendered `CompletionRequest`; its answers are validated, extracted, judged and scored like a model's; the alias needs no price or key; unknown system names, names that collide with a provider model id, and a system listed outside `models` exit 2 before any call; the cache key covers the whole case and the adapter `version`, so a rerun calls nothing and a changed `meta` or `version` asks again; transient failures are `transport` records and other exceptions stop the run.
**SUT-02** `Case.meta` holds free-form frozen JSON; a JSONL `meta` object reaches the system adapter, task scorers and slices (including `prior_turns`); a non-object `meta` is a dataset error naming the line; a case with empty `meta` serialises exactly as in v0.1.
**TSC-01** Every `TaskConfig.scorers` name outside the benchmark set is resolved before any call (unknown name exits 2), runs once per record inside `evalkit run` with case, completion, model, claims, verdicts and scores, and appears in `records.jsonl` (`task_scores` with value, version, details), `summary.json` (`ModelSummary.task_scores` mean with 95% CI over all cases) and `report.html` (escaped column per scorer); a raising scorer exits 2 naming scorer and case; a non-finite value is refused; rerunning is byte-identical and calls no model.
**SLC-01** `TaskConfig.slices` produces `RunSummary.slices`, one entry per field, value and model, with n, error counts and 95% bootstrap intervals computed over that slice's cases only (checked against an independent computation), per-judge figures only when judging is complete, `(none)` for cases missing the field, a refusal for non-scalar values; the manifest keeps the slices so `evalkit report` re-renders identically; the report shows an escaped Slices section only when slices exist.
**BWC-01** For v0.1 configs, tasks and adapters nothing changes: the golden summary and report are byte-identical, run ids and config hashes match v0.1 values, v0.1 results fixtures load, a v0.1-style `ModelAdapter` and `@scorer` plugin still work; new fields are omitted when empty; version is 0.2.0 in `pyproject.toml`, `evalkit.__version__` and `uv.lock`, with a changelog entry; the public API contract lists the new names.
